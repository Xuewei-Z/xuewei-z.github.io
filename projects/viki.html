Viki — an AI agent for the whole company's Slack

An internal Slack agent that answers project and status questions across GitHub (145+ repos), Linear, Slack, Google Drive & Workspace, Figma, and Canva.

The problem

Teams work across U.S. and international time zones. Finding out who owns a project, or where it stands, usually meant asking in chat and waiting hours for a reply. The answer was already somewhere — in code, tickets, or past threads — but spread across six tools.

What I built

  • Agent core: native tool calling with a bounded 3-round re-planning loop and a latency budget, so the agent can try again without running forever.
  • Memory: session memory with query rewriting, so follow-up questions like "and who reviewed it?" make sense.
  • Grounded answers: two-stage RAG with an explicit "I don't know" fallback. Citations come only from retrieved data, so the agent can't invent links.
  • Team workflows: leads @mention Viki in channels to recap discussions and turn meeting notes into Linear tickets.
  • Safe actions: tools exposed through an MCP server, as the base for human-approved actions.

How I measured it

Every release is gated by an eval suite (91–94% routing accuracy). I also mine per-query logs to tell real regressions apart from capability gaps — questions the agent was never built to answer.

What didn't work

Retrieval-score confidence looked like an easy way to decide when an answer was trustworthy. I tested it before building on it and found it unreliable, so I dropped it.

Shipping it

Deployed on Azure with FastAPI and Docker. CI/CD on GitHub Actions rolls back automatically if a health check fails. Timeouts and retries handle a high-variance LLM backend.
